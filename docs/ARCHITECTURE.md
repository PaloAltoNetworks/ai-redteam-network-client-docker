# Architecture

## Stack

- **Bash** — single script, `set -euo pipefail`, shebang `#!/usr/bin/env bash`.
- **curl** — all HTTP: OAuth2, SASE API, registry v2 tag listing. HTTPS-only (`--proto =https`).
- **jq** — JSON parse and JSON body construction (no manual escaping).
- **Docker** + **Docker Compose** (v1 or v2) — runs the client container from a generated, hardened compose file.

`curl` + `jq` are the only hard startup dependencies (checked by `require_basics`). Docker is checked per-mode, so `--init` can generate config on a host that does not run the container.

## Why this stack

A Bash script is the right size for the job: orchestrate API calls, write config files, invoke Docker. The target hosts already have `curl`, `jq`, and Docker. A compiled binary (Go/Rust) would add a build + signing pipeline for what is a thin orchestration layer; per-distro packages (`.deb`/`.rpm`) would multiply the release matrix without removing the Docker requirement. See [DECISIONS.md](DECISIONS.md) ADR-001/002/003.

## Single-file layout

No source tree — the whole tool is `setup-panw-network-client.sh`. Internal organization is by function prefix:

| Group | Prefix / names | Role |
|---|---|---|
| Modes | `do_init`, `do_install`, `do_status`, `do_validate`, `do_diagnose`, `do_list_versions`, `do_check_update` | One per CLI mode; dispatched from arg parsing |
| API layer | `api_*` (`api_authenticate`, `api_call`, `api_list_channels`, `api_get_stats`, …) | OAuth2 + SASE API calls |
| Registry | `registry_list_tags`, `resolve_registry`, `discover_image_from_api` | Tag discovery (curl/jq), region→registry mapping |
| Interactive | `select_*`, `prompt_*` | Region / channel / version selection |
| Config | `load_env`, `migrate_env_if_needed`, env writers | Read/write/migrate `.env` + `.env.runtime` |
| Helpers | `die`, `info`/`warn`/`error`, `http_probe`, `log_deploy`, `new_auth_tmp` | Cross-cutting utilities |

## Generated artifacts

| File | Generated by | Committed? |
|---|---|---|
| `.env` | `--init` | No (gitignored) |
| `.env.runtime` | install | No (gitignored) |
| `docker-compose.yml` | install | No (gitignored) |
| `deploy.log` | every install/pull | No (gitignored) |

## Separation of concerns

- **API layer** (`api_*`): transport + auth only; callers parse the JSON they need.
- **Registry** (`registry_*`): tag discovery is a plain registry v2 call, independent of `docker pull`.
- **Config writers**: own all secret-file handling — `umask 077` subshell, `chmod 600`, never echo secrets.
- **Mode functions**: orchestrate; they do not embed low-level curl/jq plumbing inline.

## Container hardening

The generated `docker-compose.yml` applies: `read_only: true`, `security_opt: [no-new-privileges:true]`, `cap_drop: [ALL]`, `mem_limit: 512m`, `cpus: 1.0`, `pids_limit: 256`, `restart: unless-stopped`. No healthcheck (distroless image — see [DECISIONS.md](DECISIONS.md) ADR-005).

## Security model

- API credentials passed via `--header @file`, never inline (invisible in `ps`).
- Credential functions disable shell tracing (`set +x`).
- Auth-header temp files registered for cleanup on `EXIT INT TERM HUP`.
- Secret files written under `umask 077`, then `chmod 600`.
- HTTPS-only on every call (`--proto =https`).
- `deploy.log` records image digests + timestamps, never secrets.

## CI / release

- Lint workflow: ShellCheck + shfmt (2-space) on push and PR.
- Release workflow on tag push: builds, attaches the `.sh` + Sigstore build-provenance attestation, body is changelog-only.
- All GitHub Actions SHA-pinned (org rule).
